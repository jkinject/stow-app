**B를 추천한다.** 찾기 탭의 사진 격자와 역할이 분명히 다르면서도 ‘집의 기억’이라는 약속에 가장 가깝다. 이미 입력한 소비기한을 유용한 순서로 보여주고, ‘이걸 먼저 쓰자’는 한 번의 지정이 레시피로 이어진다. C의 보관 기능보다 구현·운영 부담이 작고 A보다 새 탭의 이유가 선명하다. 다만 성공의 전제는 소비기한 입력이다. 빈 상태에서 기존 물건의 소비기한 입력까지 이어지는 길을 먼저 검증해야 하며, 임박 0개를 ‘우리 집 음식은 안전하다’고 표현하면 안 된다.

## 다섯 결정의 반영

- **Q1:** 음식 = `expires_on is not null`. 카테고리·새 음식 컬럼 없음. 식품인데 기한이 없으면 보이지 않는 점을 모든 빈 화면과 첫 안내에서 설명. 반대로 약·화장품이 들어오는 한계도 각 설계에 기록.
- **Q2:** 음식 전부를 서버에서 자동 조회. 화면 필터가 입력을 줄이지 않음. 선택하는 것은 소진 우선뿐. 지정한 재료 모두를 **각 추천 요리가 실제로 사용**해야 함.
- **Q3:** 탭 진입 시 생성 금지. 재료 집합+우선 재료+언어 등으로 서버 캐시. 입력 4,000/출력 2,048토큰, 가구 3회/UTC일, 전역 무료 quota 이하 제한. 사진 없음. 결제 미연결 Free 프로젝트가 기본이고 유료 fallback 없음.
- **Q4:** 가구당 현재 세트 하나를 DB에 저장. 재진입·앱 재실행·가족 기기·언어 변경으로 바뀌지 않음. 첫 추천 이후 **‘다른 레시피 추천’ 성공 때만** 현재를 교체. 수량 차감·만들었다·기능 연동 없음. C의 보관은 레시피 문서만 저장.
- **Q5:** 더보기 → 집 관리 그룹 첫 행 ‘살 것’. 박스 라벨 인쇄보다 위, 장소가 없어도 표시. 기존 트리거·shopping_list·읽기 전용 동작 유지.

## 비용과 고정 결과에서 놓치기 쉬운 것

‘같은 조합은 재호출 안 함’과 ‘다른 레시피 추천’은 동일한 규칙으로 처리할 수 없다. 일반 조회·재시도에는 조합 캐시를 쓰고 **사용자의 명시적 재추천만 generation을 올리는 예외**로 둔다. request_id로 연타/재전송을 묶고 가구 잠금·revision 비교로 가족의 동시 요청이 결과를 덮어쓰지 않게 한다. 현재 세트에는 TTL이 없으며 날짜·재고·언어 변화는 안내만 바꾼다. 상세 규약과 SQL 골격은 각 안에 독립적으로 포함했다.

운영 기본은 무료여서 API 청구 $0다. Flash-Lite도 평가 후 전환할 수 있지만 무료 구성에서는 현금 절감이 없으므로 Flash부터 시작한다. 유료 가정의 상한 계산·무료 quota 소진·실패 시 횟수 차감·캐시 저장 상한·무료 API 데이터 사용 조건은 각 안의 비용 절에 있다. 가격/모델은 배포 직전 다시 확인한다. 확인 근거: [Google 요금표](https://ai.google.dev/gemini-api/docs/pricing), [결제와 무료 티어](https://ai.google.dev/gemini-api/docs/billing), [JSON 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output).

## 목업 보는 법

각 HTML을 로컬 브라우저로 열면 **폭 402px의 폰 4개가 한 줄**에 놓인다. 작은 화면에서는 보드가 가로 스크롤되고 폰은 줄바꿈하지 않는다. 각 폰 내부는 세로 스크롤된다.

1. 탭 진입(음식 4개). A/B는 첫 추천 전, C는 저장 결과가 있는 재진입.
2. 소진 우선 지정. A는 한 칩, B는 두 토글, C는 두 개를 고른 바텀시트.
3. 서버에 고정된 결과 두 레시피. 단계 펼침은 동작하며 호출 없음.
4. 음식도 저장 결과도 없는 첫 방문. 저장 결과가 있는 가구는 음식이 0개가 되어도 결과를 유지한다.

상단 라이트/다크 버튼은 실제 동작한다. 레시피 펼침과 C의 보관 버튼은 시안 확인용 로컬 동작이다. 다른 버튼은 정적 상태 비교 안내만 보여주며 실제 앱 이동·DB 저장·API 호출은 하지 않는다. 음식 탭의 채택 아이콘은 그릇이며 페이지 아래 접시·냄비 후보도 그렸다. 사진은 회색 토큰 박스와 라벨이다. 외부 폰트·이미지·스크립트·네트워크 의존성이 없다.

## 산출물 검증 범위

HTML 3개에 4개 프레임/탭바, 인라인 SVG 규격, 외부 리소스 부재, 토큰 값 일치, JavaScript 구문을 정적으로 검사했다. 설계 문서의 JSON 블록 구문과 상대 링크도 확인했다. 앱 코드·기존 SQL·progress.txt는 작업 전후 해시로 172개 파일에 변경 없음을 확인했다. 연결된 브라우저가 없고 Safari 컴퓨터 제어가 허용되지 않아 실제 브라우저 렌더링·클릭 검증은 완료하지 못했다. HTML의 실제 타이포그래피/스크롤은 로컬 브라우저에서 최종 확인이 필요하다. 앱 테스트·DB 마이그레이션·배포·실제 Gemini 요청은 이 설계 작업에 포함되지 않는다.
