## 배운 것 / 함정
1. `@expo/vector-icons` 를 **컴포넌트로** import 하면 jest 가 ESM 변환에 걸려 테스트가
   아예 못 돈다. **글리프맵 JSON** 을 import 하면 앱과 테스트가 같은 근거를 본다.
2. 아이콘 이름 오타는 화면에서 **빈 네모**로만 드러난다. 타입(keyof glyphMap)이
   'fishing' 을 컴파일 시점에 잡았다 — 팩에 없는 이름이었다(→ 'fish').
3. 색 대비 기준을 **4.5:1 로 잡았다가 멀쩡한 색 5개가 걸렸다.** 타일에 얹히는 것은
   큰 아이콘이라 WCAG 기준이 **3:1**(비텍스트 요소)이다. 기준을 잘못 잡으면 테스트가
   옳은 것을 막는다. 실제로 미달인 색은 하나뿐이었다(#CA8A04 2.94 → #B45309 5.02).
4. `색 + 'AA'` 로 투명도를 붙이는 규칙이 MovePicker 안에만 있었다. 카테고리 배지에서
   또 필요해져 `lib/theme` 의 `tinted()` 로 올렸다. 두 곳에 적으면 한쪽만 고쳐진다.
5. 아이콘 **폰트**가 들어가므로 `expo prebuild` 부터 다시 해야 한다.

  어긋난다. 칸은 정수로 내리고 **남는 폭은 간격에** 나눈다 — 소수 폭을 그대로 쓰면
  픽셀 반올림으로 마지막 칸이 다음 줄로 밀린다(8열이 7열로 보인다).
  ⚠ 첫 시도에서 `width: cell` 이 실제로 안 들어갔다. 앞선 편집으로 들여쓰기가 바뀌어
    치환이 조용히 실패했고, 칸이 **내용 크기**로 잡혀 한 줄에 13개가 됐다.
    치환 후에는 결과를 grep 으로 확인해야 한다.
· 색 원도 10개를 한 줄에. 전에는 8개 뒤 둘째 줄에 2개만 남았다.
· 실측: 입력칸·색·아이콘 모두 좌 45px / 우 1034px 로 동일

## 자체 코드 점검에서 찾은 결함 2건
1. `move(i, ...)` 의 i 가 **걸러진 목록**의 자리인데 함수는 전체 목록에 적용했다.
   지금은 편집 중 거르지 않아 우연히 같지만, 그 조건이 바뀌면 엉뚱한 줄이 옮겨진다.
   → id 로 찾도록 바꿨다.
2. 순서 저장이 실패해도 `localOrder` 가 남아 **저장 안 된 순서가 화면에 계속** 보였다.
   주석에는 "무효화가 되돌린다" 고 적어 뒀는데 이 값이 그걸 막고 있었다.
   → onError 에서 버리고 알린다.
